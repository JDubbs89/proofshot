# Proofshot 0.3.0 design draft

## Goal

Add a useful, optional PySide6 GUI alongside the existing CLI. The GUI should let users discover and create projects, capture and manage screenshots, browse images, inspect metadata, modify columns, and package selected project evidence without creating a separate project model.

## Product decisions

- A workspace stores ordered discovery paths in a versioned JSON file under `~/.config/proofshot/`.
- Each discovery path contributes its immediate child directories to the project browser.
- Resolved duplicate projects appear once. Missing paths and unavailable projects remain visible with an actionable unavailable state.
- A project is an independent directory; its project files remain authoritative.
- New projects can be created inside a selected discovery path and initialized immediately.
- The project display name is the directory name; the full path is secondary information.
- PySide6 is optional. Installations provide `proofshot --gui`, `proofshot-gui`, and a desktop launcher.
- GUI edits persist immediately through shared services. Destructive actions require confirmation.

## GUI surfaces

### Project browser

Manage discovery paths, refresh them, create projects, initialize or upgrade legacy projects explicitly, and open a project. Discovery refreshes at startup, after path changes, on manual refresh, and when a path is selected.

### Project view and gallery

Show project columns and screenshots in a filterable gallery/list. Refresh on navigation and through a visible refresh action. Selecting an image opens Image Detail.

### Image Detail

Show the full-size image and read-only derived metadata: filename/path, project, column, index or range, dimensions, file size, and manifest status. Allow confirmed image removal, but do not edit manifest fields in this release. Captions are future user-authored metadata, not part of 0.3.0.

### Column management

Support adding, renaming, removing, reordering, and editing global or per-column naming templates. Preserve Form/Proof removal protections and existing CLI semantics. Persist explicit order so numeric selection remains deterministic across CLI and GUI.

### Capture and packaging

Reuse the existing screenshot provider workflow for Form, Proof, and custom columns. Refresh the gallery after successful capture. Expose ZIP packaging by column and index range, with an output-path chooser and result status.

## Architecture direction

Extract reusable project, workspace, manifest, image, configuration, capture, and packaging operations from CLI orchestration as needed. GUI code should call those operations directly. Keep Qt-specific state and presentation out of the domain/service layer.

## Error behavior

Use inline status plus actionable dialogs. Errors should identify the failed operation and cause, preserve the current window, and offer a relevant retry, details, or open-folder action when possible.

## Verification bar

Add service-level tests for workspace discovery and persistence, project creation/initialization, config and column mutations, ordering, manifest/image-detail mapping, and packaging. Add GUI smoke tests covering launchability and the principal browser/gallery/detail paths.

## Release/install documentation

Document an optional GUI install extra and the desktop launcher. Keep the CLI installation lightweight and retain support for the existing Linux distribution installation model.

## Deferred

- Captioning and other user-authored image metadata.
- Full editable manifest metadata.
- Continuous filesystem watching.
- Recursive discovery.
- GUI-owned project registry/database.
